# OKF v0.2 source selection and limits

Reviewed canonical source: [GoogleCloudPlatform/open-knowledge-format](https://github.com/GoogleCloudPlatform/open-knowledge-format),
commit `ad30107c31c06aec8a7d5636e0d1058118604e6f`. The supplied
knowledge-catalog snapshot `7a0224426fcd84418399d0d0c1ef1998a50a4053` marks its
OKF subtree frozen and moved. Both pinned SPEC files are identical v0.2.
Exact selected source identities are in okf-provenance.json.

## Selected capability

The coherent mechanism is portable Markdown/YAML concepts, optional discovery
indexes, connected sources/definitions, lifecycle and review information. Existing
owners gain original project-handoff guidance and an original fictional bundle;
AI SEO's existing reference gains corrected known-consumer website-export guidance.
No Acme files, upstream implementation or substantial prose are copied.

The source specification was read in full. Supporting implementation and tests were
read selectively as source, including an independent review. No upstream programs,
tests, models, browser renders or BigQuery calls were executed. Recorded file hashes
prove selected byte identity, not a full audit or demonstrated model effectiveness.
The local fixture tests are not a general OKF validator, rendering test, executable
attestation, interoperability certification or measured retrieval/SEO improvement.

## Corrections and omissions

- Metadata is advisory: `human:` is not authentication and `verified` is not bound
  to a content revision. Missing optional metadata remains consumable.
- Source, projection, index and delivered revision are separate. Current timestamps
  alone do not establish factual freshness, authority, completeness or approval.
- The sample attester trusts supplied receipts and ignores parameter values; its
  regex SQL normalization is not SQL-semantic comparison. Stronger runtime claims
  need a trusted definition, authoritative run evidence and actual binding checks.
- Reference viewer and producer have link/freshness and ingestion limitations.
  The local example uses relative links and does not import that runtime.
- Automatic BigQuery/web enrichment, generated summaries, graph browsing and
  executable computation are omitted. They may merit separate integration for a
  matching project; they are not required to create or read a useful bundle.
- No new skill, service, dependency, provider, automatic capture, public upload,
  memory export or global instruction change is introduced. Prime's continual
  harness remains its durable learning authority; project data stays project-scoped.

## Primary context

[Google Cloud's announcement](https://cloud.google.com/blog/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing)
discusses v0.1, proof-of-concept producer/viewer and Knowledge Catalog ingestion.
This is not evidence of Google Search adoption. The canonical pin is now v0.2.
[Google Search guidance](https://developers.google.com/search/docs/appearance/ai-features)
says AI Overviews/AI Mode require no new machine-readable files. This does not prove
that no other consumer supports OKF; judge actual consumer need and compatibility.
Saved retrieval identities are recorded for evidence, not a promise URLs stay fixed.
