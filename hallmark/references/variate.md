# Hallmark + Variate: one design round, one owner

Hallmark supplies the design rationale. Variate owns registration, baseline/archive
preservation, numbered variants, live switching, request claims and cleanup.
Read the installed Variate `SKILL.md` for actual CLI commands and safety rules;
Hallmark must not implement a second queue, preview server or acceptance protocol.

## Before the round

Confirm one target file and the existing design system. If an outcome needs shared
CSS, packages, fonts, several components or token changes, either complete those as a
separate approved change before registration or choose a file-local direction. Do not
pretend Variate's single-file round can safely switch a multi-file design system.

## During the round

- Existing position 1 is the baseline. Do not edit it, the live target, shared styles,
  tokens, routes, `design.md`, product context, or other variants to support a draft.
- Read shared context, but write only the new numbered file(s) assigned to you and
  authorized plan metadata. Hallmark never creates `tokens.css` or `.hallmark` logs.
- Use the target's available imports/assets/tokens. A complete replacement must remain
  valid in that file's existing role. If the boundary cannot support a direction,
  disclose the blocker instead of quietly creating a dependency.
- Give each option a structural distinction and a tradeoff. The user's brief governs
  variety: do not force new fonts, colours or navigation merely to differ.
- One coordinator calls Variate. Parallel drafters only write their assigned new
  variants. The coordinator owns `plan.json`, CLI mutations and the request consumer.
- Run advisory lint plus native project tests and inspect each option in a real browser
  when available. A screenshot or self-score alone is not a build/interaction check.

## Choosing and finishing

Use Variate's use/narrow/end commands; do not copy over the live target by hand.
Respect saved keep/refine hashes, ownership, redelivery, unknown requests and cleanup
refusals. Hallmark does not acknowledge requests. Browser clicks do not wake an idle
agent; resume only on a relevant user request. Never wait in a polling loop.
After acceptance, verify the saved file and final diff. Full end deliberately deletes
alternatives and archives. Optional portable design documentation comes only after the
round is closed and only if requested. Do not leave an unattended preview behind.
