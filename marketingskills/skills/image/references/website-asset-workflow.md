# Connected website assets

Use when a requested website needs a related family of stills or short clips,
including Higgsfield work. Image owns the stills and delivery variants; Video owns
motion and final media. Hallmark/Cinematic UI and the actual project own usable
page design. This is an optional production workflow, not a compulsory new brand,
generated kit, document format or website platform. Existing assets and a still,
type-led page are valid. A prompt-only handoff is a complete result when requested.

## 1. Define the asset family from the page

Read the approved brief, real content, brand assets and target layout. Name each
needed slot, its useful message, dimensions/crop, text-safe area, destination and
acceptance checks. Do not buy a hero, icon set, film and cover merely because a
catalogue lists them. Keep real logos, staff, products, testimonials and UI factual;
missing evidence does not authorize invented faces, endorsements or screenshots.

Use the project's existing asset notes; create a separate pack only if it makes
the handoff useful. Record supplied/approved facts separately from proposed art
direction and unknown details. A visual board proposes composition, not business
facts or semantic HTML. Inspect it, then translate hierarchy and spacing into the
site's tokens, real copy and accessible components; do not trace illegible labels.

## 2. Lock a shared direction and reference roles

Choose the few constants that make this family coherent: subject identity,
light/material behavior, palette roles, viewpoint relationships and copy treatment.
State what may vary by slot. Reuse approved logo/type masters; exact production
text is usually composed separately, not entrusted to an image model.

For each permitted reference name its source revision, role and exclusions:
identity/product, composition, lighting/material, or motion. State whether to
preserve the full subject, selected attributes or only a loose relationship.
A style reference must not silently replace a product, person, logo or claim.
Inspect supplied images before describing them. Public availability is not reuse
permission; uploads and likeness/voice use need the relevant authority.

Plan view coverage from the actual shot. A turn revealing a product's back needs
real supporting views or an explicitly fictional design exercise. A generated
reference sheet cannot establish unseen geometry. Obtain missing evidence, shorten
the move or choose another shot. Keep annotations on a copy, with a clean master.

## 3. Write connected, usable prompts

For a still, specify subject, setting, light/material, composition and output role.
For image-to-video, use the approved starting asset and describe the intended
change: subject action, camera behavior, pacing and endpoint. State critical
invariants without treating a prompt as proof they survived.

For several shots, keep one shared direction and a named reference map, then give
each shot a stable ID, source revision, purpose, duration, start/end state and
continuity into the next. A local override changes only that shot; a global change
requires reviewing all affected prompts and outputs. Assemble a standalone prompt
at handoff so the recipient need not reconstruct scattered chat fragments.

Choose duration and scene count from the content and the selected model's actual
contract, not fixed word limits, a mandatory hero hold or a universal 15-second
rule. Account for edits, overlaps and intentional holds in the final runtime.
Single-film scroll chapters share one timeline; repeating a full clip per chapter
restarts it. Multi-leg sequences need inspected adjacent frames and motion, not
only matching endpoints. Video's export checks and Cinematic UI's pacing guidance
remain applicable; a rendered film is not interactive 3D geometry.

See the original [Luma Desk asset pack](website-asset-pack/index.md) for a connected
brief, reference map, prompts, a revision example and delivery plan. Its fictional
assets are absent and all generation/inspection states are explicitly unperformed.

## 4. Cross the execution boundary deliberately

Prompt drafting does not grant permission to install tools, access an account,
upload files, train an identity, spend or publish. When Higgsfield is selected, read
[the provider guide](../../../tools/integrations/higgsfield.md). Other providers
use their approved project integration; Higgsfield is not mandatory here.

Agree the exact inputs/destination, total budget, attempt ceiling and stop rule
before paid work. Reuse an existing adequate authorization rather than asking at
every step. Include setup, preprocessing, all variants, video/audio/assembly and
retries in the estimate. Unknown cost is not zero. A missing estimator needs a
bounded approved alternative or a decision, not a submission to discover the bill.

Record request/job identity in existing task state. Start independent approved
jobs together when useful; dependent shots wait for inspected source frames.
Inspect current job status after a timeout before retrying an uncertain submission.
A retry must not silently create a duplicate paid job. Recover the existing result
when possible; stop at the approved limit and report partial output honestly.

## 5. Inspect, revise and select

Inspect actual assets, not just the prompts or success URLs. Compare the family
and each critical detail: identity, exact labels, intended crop, anatomy/geometry,
light continuity, motion, unwanted marks and supported factual claims. Review the
final-resolution output; a draft is not proof of final fidelity. A generated board
cannot certify the delivered webpage.

Diagnose the defect before rerolling. Hold relevant inputs fixed and change the
smallest useful variable, or correct a known conflicting prompt/reference. Multiple
different failures do not prove the prompt is right. Do not apply a universal
acceptance rate, model ranking or minimum iteration count. Stop, use an approved
still or report a gap when budget or fidelity cannot support more generation.

Keep accepted masters, rejects and served derivatives distinguishable. Tie an
approval or check to the asset/prompt/reference revision it actually covered.
Changed meaningful content invalidates affected approval and inspection, even if
the scene ID or checkbox stays the same. A crop-only change needs crop review;
a new product reference can invalidate the still, derived motion and both crops.
Keep unrelated assets valid. This is project delivery state, not an automatic
cross-project memory, telemetry log or scheduled refresh system.

## 6. Deliver assets into the real website

Hand over only selected assets with role, source/approval revision, actual path,
dimensions, format, measured bytes, crop/focal treatment and outstanding checks.
Keep editable originals separate from flattened renders and optimized derivatives.
Use the site's existing asset pipeline; verify actual encoded dimensions and files,
not model-requested values or guessed output URLs. Check SVG inputs for active or
external content before use; repository licenses do not clear fonts or likenesses.

Let real layout needs decide responsive variants. Keep informative text in HTML,
mark decorative imagery appropriately, and describe meaningful observed content
rather than copying its prompt as alt text. Important initial imagery should not
wait behind indiscriminate lazy loading. Avoid forcing motion, huge films or a new
animation library into a site that does not need them.

For motion, provide a relevant poster and accessible static meaning. If the lesson
requires several states, one poster is not enough: retain the necessary views and
captions. Use approved native/local-browser checks for crop, keyboard behavior,
reduced motion, loading/failure, forward/reverse seeking and lifecycle as applicable.
Measure transfer/decoder behavior against the project's budget. Report unavailable
checks; source inspection, typecheck and generation success do not prove rendering.

Deliver a short inventory of what is ready, intentionally excluded, missing or
unverified. Local completion, public deployment and community-feed listing are
separate decisions. Do not call a public production URL a private preview.
