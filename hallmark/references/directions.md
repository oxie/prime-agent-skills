# Composition directions

Choose for content and user action, not novelty. The user and project system
win. Keep working information architecture unless change is authorized.
For one component, skip page composition. Palettes: [themes.md](themes.md).

## All 21 macrostructures

Names and shapes are from upstream Hallmark; fit and cautions are curated here.
Choose by content, not a checklist.

| Structure | Shape / useful fit | Tradeoff or check |
| --- | --- | --- |
| 01 Bento Grid | Unequal tiles; many entry points | Choose a focal tile; keep reading order |
| 02 Long Document | Continuous prose; essay or case study | Add scan points and findable actions |
| 03 Marquee Hero | One large statement or image; brand launch | Do not delay essential explanation/actions |
| 04 Stat-Led | Number plus meaning; evidence-led story | Real source, timeframe, denominator, caveats |
| 05 Workbench | Product captures with task captions | Needs real proof and readable crops |
| 06 Conversational FAQ | Questions with short answers | Keep core facts outside closed panels |
| 07 Manifesto | Large declarations; mission | Can delay task completion |
| 08 Photographic | Image bands with captions; visual product | Check rights, crops, alternatives |
| 09 Quote-Led | Attributed quote then case evidence | Real, authorized quotes; retain context |
| 10 Specimen | Margin labels, large type, asymmetric spans | Collapse margins on mobile |
| 11 Catalogue | Equal product/variant cards; comparison | Show differences beyond thumbnails |
| 12 Letter | Personal prose, salutation, sign-off | Intimate but slow for transactions |
| 13 Index-First | Categorized links; docs or archive | Clear destinations beat decoration |
| 14 Narrative Workflow | Sequential stages with proof | Needs a genuine sequence |
| 15 Split Studio | Paired claim and proof in two columns | Keep semantic order when stacked |
| 16 Feature Stack | Persistent explanation beside detail views | Give sticky layout a normal-flow fallback |
| 17 Type Specimen | Typeface across sizes/features | Fits typography as the product |
| 18 Portfolio Grid | Project thumbnails to case studies | Filters need empty states and stable focus |
| 19 Map / Diagram | Spatial nodes, links, legend | Offer a linear equivalent |
| 20 Ecosystem Index | Featured/latest/category discovery | Too many rails dilute focus |
| 21 Component Playground | Interactive preview and code | Working examples, states, copy feedback |

## Seven proposed recipes

Adaptation suggestions, not upstream rules. Keep branding; themes are optional.
Never invent metrics, quotes, logos, prices, or product screenshots.

1. **Developer tool / Workbench.** Task headline → real request/result →
   annotated steps → limits and docs. Cobalt or Midnight. Result leads; code
   stays selectable. Strong proof, but long code competes with the message.
   Stack caption before example on mobile.
2. **Evidence-led service / Stat-Led.** Verified outcome + meaning → method
   and caveats → case detail → contact. Almanac or Newsprint. Number leads;
   source stays adjacent. Aggregation can mislead. Without real data use prose.
3. **Editorial launch / Long Document + Specimen.** Title → premise → argument
   with margin headings → evidence → next step. Specimen or Garden. Start near
   60ch for body; headings aid scanning. Depth costs speed. Move margin labels
   into normal flow on mobile.
4. **Visual shop / Photographic + Catalogue.** Product image, name, action →
   comparable items → material/size facts → delivery. Atelier or Studio.
   Product leads. Immersion costs bandwidth; use approved images and keep key
   crops intact. Keep buying information visible.
5. **Creative practice / Portfolio Grid + Split Studio.** Positioning → selected
   work → expanded claim/proof pair → contact. Grid or Editorial. Work outranks
   biography; rank projects rather than equalizing all. A short list needs no
   filters. Keep project names available when images fail.
6. **Learning product / Narrative Workflow.** Learner goal → real stages →
   sample exercise → progress explanation → start. Hum or Coral. Exercise
   leads. Playfulness can distract; feedback explains real progress. Stack
   stages on mobile; motion must not carry essential meaning.
7. **System library / Index-First + Component Playground.** Category index →
   working example → relevant states → code → related items. Terminal or
   Cobalt. Navigation and preview outrank sales copy. Density needs keyboard
   access and visible focus. Confine code overflow to its region, not the page.

## Small component guidance

- **Navigation:** visible links for short sites; groups for real depth. Search
  supplements links; no mandatory command palette or floating bar.
- **Sections:** inline headings for prose, margin headings for scanning, tables
  for comparison. Preserve semantic headings when styled as labels.
- **Actions:** links navigate; buttons act. Label forms, keep errors by fields,
  preserve entered values. Use an inline form only if it shortens the task.
- **Cards:** one clear destination; no nested interactive targets. Show useful
  comparison facts. Real screenshots need no decorative browser chrome.
- **States:** cover relevant default, hover, focus, active, disabled, loading,
  error, success. Static content does not need invented interactive states.
- **Footer:** credits for small pages; categories for deep sites. Forms belong
  only to a real signup flow.

Verify in the project's runtime: narrow/wide views, long content, keyboard,
zoom, and reduced motion. Fix overflow causes, not by hiding root content.
Measure contrast on rendered pairs; all catalogue contrast is UNVERIFIED.
Report actual checks and limits.
